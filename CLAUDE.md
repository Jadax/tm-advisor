# TM Advisor

Single-file Tampermonkey userscript (`TM_Advisor.js`) for trophymanager.com. One IIFE, numbered `SECTION` blocks — the file's header comment holds the authoritative table of contents. Jump straight to the section you need; never scan the whole file.

`TM Guide/` is third-party reference material (official wiki PDFs + community userscripts). Read-only: consult it to confirm formulas, never copy a script wholesale.

## Rules

- Reuse before adding: grep for an existing helper first (`ensureR5`, `slotRating`, `bestFormation`, `buildMatchPlan`, `xiImpact`, `youthPace`, `bucketFor`, `sideFor`, `parseMoney`, `fmtMoney`, `bindBtn`, `esc`, `badge`, `costRow`, `playerLink`, `ago`, `fetchDoc`, `fetchMatchJson`, `tmPost`, `sleep`). One helper per concept.
- Game formulas (R5, Sell-to-Agent, Max Sell Price, training/growth) must trace to a cited source — official wiki page or named community script, in a one-line comment. Never invent numbers. Heuristics must be labelled as heuristics in both comments and UI copy.
- Escape every game-supplied string with `esc()` before it enters an innerHTML template — club/player names are attacker-controlled.
- Comments only for non-obvious WHY (game quirks, confirmed-surprising formulas, past bugs prevented). No restating code.
- After any edit run `node --check TM_Advisor.js` — that is the entire verification loop. No build step, no tests.
- Bump `@version` in the userscript header on every functional change.
- Public repo: https://github.com/Jadax/tm-advisor (branch `main`; user-facing docs live in `README.md`). After any change that bumps `@version`, commit and push automatically — no need to ask. Format: `vX.Y.Z: <one-line summary>`. Never commit `TM Guide/` or `.claude/` (gitignored).
- Keep replies terse: the change and where it lives, ≤2 lines of summary.

## Data sources (all same-origin, game's own endpoints)

- `/ajax/players_get_select.ajax.php` — full real skills for any club's squad
- `/ajax/match.ajax.php?id=` — lineups + mentality/style/focus per side, full match_data
- `/ajax/scouts_get_reports.ajax.php` — scout rec/potential for your reported players
- `/ajax/tooltip.ajax.php` — per-player skills/SI/routine/wage (precise age incl. months)
- Favourite positions arrive in TWO formats: display (`players_ar`, tactics page, players_get_select: "D/DM L", "M LR", "OM C, F") and codes (tooltip.ajax, youth.ajax: "dl,dml", "mr,ml"). Engine code expects display — convert at ingestion with `displayFp`. Codes read as display silently zero TM's position penalty (seen live).
- `players_get_select` field traps: name is `player_name` (no `name`); stars are `rec_count` — `rec` is an unrelated raw ≈14 figure. Match-report line-ups (`match.ajax.php`) carry `rec` in stars + `routine` + `position` (slot) per player, also pre-match for the next fixture.
- `/ajax/fixtures.ajax.php` POST `type=club&var1=<clubId>` (or `type=league&var1=<country>&var2=<div>&var3=<group>`) — `{ "YYYY-MM": { matches: [{id, date, hometeam, awayteam, result, matchtype}] } }`; unplayed = no `result`
- `/ajax/youth.ajax.php` POST `{type:'get'}` (the page's own load call, read-only) → `{players: {id: {player_name, favposition 'dc'|'gk'…, age, wage, fee, strength…/handling…/aerial/oneonones}}, cash, squad_size}`; skills are hidden until revealed; NO SI. Cards render as `div.youth_player#youth_player_<id>` (not table rows). Reports arrive weekly (Saturday).
- Training: `/ajax/training_get.ajax.php {type:'get'}` → `players_list[{id, fp, training: groupId, training_custom}]`; move = `/ajax/training_post.ajax.php {type:'player_pos', player_id, team_id}` → `{success}`. Groups 1 Technical (tec pas set), 2 Fitness (str sta pac wor), 3 Tactical (wor pos pas), 4 Finishing (fin lon hea), 5 Defending (mar tac pos hea), 6 Winger (cro pac tec), 7 Goalkeeping — from the training page's `team_tooltips`. Guide: 25% of standard training goes to focus skills, 75% random. These standard groups are only the FALLBACK while custom training is on — the user HAS Pro (SESSION.is_pro true / pro_days 1111 on most pages; read false/0 once on /training/, so don't trust it alone). Every player is on custom training, so the copilot never touches the groups (user, 2026-11-02).
- Match reports: `report[minute][].parameters[]` carries `goal{player}`, `shot`, `sub{player_in, player_out}`, `mentality_change{team, mentality}` — an opponent's past conditional orders are read from these (`opponentInGame`). Each event also has `club` (the attacking side) and `type` whose letter prefix is the attack build-up (cou/kco direct, win wings, sho short, klo/lon long, thr through; `p_` penalties — "TM - Season Match Analysis") → `concededByStyle`.
- Custom-training points per group by dots: 0/10/17/23/25 ("TM - Players Train" v10) — `DOT_POINTS`; 2-2-2-2-2-2 = 102.
- Custom training (Pro): read `players_get_info.ajax.php {player_id, type:'training'}` → `custom {custom_on, team (fallback group), custom: {teamN: {label, skills[], points}}}`; save = `training_post.ajax.php {type:'custom', on:1, player_id, custom[points_spend]:0, custom[player_id], custom[saved]:'', custom[teamN][num|label|points|skills][]}` (12 dots, max 4). Groups: 1 str/wor/sta, 2 mar/tac, 3 cro/pac, 4 pas/tec/set, 5 hea/pos, 6 fin/lon. Templates + rules: Sunshine United, /forum/int/general/414096/ (posts #2-#4) — the user's own templates are identical.
- TI: `players_ar` has `ti` (this week) and `plot` (weekly TI history). Training runs once a week (Tuesday) — history is one snapshot per training week (`weekKey`), skills (`sk`) + ti included.
- Reserves (B team = SESSION.b_team): move = `players_move.ajax.php {player_id, move: 'check'|'down'|'up'}` (check first; a demotion ties the player down ≥3 games). Reserve tactics = every tactics endpoint with `reserves: 1`, settings page `/tactics/reserves/`. Own fixtures: fixtures `type=club&var1=<b_team>`.
- Youth report: hire/fire = `youth.ajax.php {type:'act', player_id, action:'hire'|'fire'}` (fire is permanent). Report rows carry `rec_stars` but no potential — the engine acts only when a potential value is present.
- Scouts: list + reports per player = `players_get_info.ajax.php {player_id, type:'scout'}` → `{scouts{…, away, returns}, reports}`; send = same with `scout_id`. Own scouts = /scouts/ table, hire list = /scouts/hire/ (same columns Sen Yth Phy Tac Tec Dev Psy; blank = 0; hire list adds "Wage: n, Sign-on fee: 6 Mil" and `hire_scout_pop(name, fee, id)`). Hire = POST `/scouts/hire/ {session_id: SESSION.id, scout_hire: 1, scout: id}` (the page's own modal form). User rule (2026-11-02, refined 11-04): keep 1 youth scout (20 Yth) + 1 senior scout (20 Sen), each with at least one more useful 20 (youth: Dev most — it judges development/bloom; then Phy/Tac/Tec peaks, Psy traits); auto-hired by value per cost (`scoutValue`/`scoutRoi`: fee + 26 wks wage; within 10% of the best ROI the more capable scout wins). Specialists (20 Sen + 20 Phy) are cheap; multi-20s are fine if the ROI holds; Sen+Yth double-20s are a waste.
- Head-to-head: GET `/ajax/match_h2h.ajax.php?home_team=A&away_team=B` → `{matches: {season: [{id, date, hometeam, result, matchtype}]}}` (`fetchHeadToHead`). Manager activity: `tooltip.ajax.php {club_id}` → `club.last_seen` ("3. November") (`fetchManagerLastSeen`).
- Routine sharing ("TM - League Squad Analyzer"): per line GK+D / DM+M / OM+F the lowest-routine starter plays at min(own + 0.25 x line max, 2nd-lowest, 40) — `shareRoutine`, applied in `pickBestXI` and `opponentXI`.
- `/fixtures/club/<id>/` HTML has NO match links (script-built) — use fixtures.ajax (`fixturesOf`). Opponent scans read 0 games until v3.20.0.
- TM simulates matches AHEAD of kickoff: once a match is locked, fixtures already carry its result — "first unplayed" then means the NEXT fixture. Anchor on a match by id, never by "first unplayed" (shifted the reserve kickoff by days once).
- Foreign players: max 5 across XI + bench (`js/tactics_v2.js`: `foreigners >= 5` blocks the drop; foreign = player `show_flag`, i.e. `country` ≠ SESSION.country) — `MAX_FOREIGN`/`isForeign`, enforced in `pickBestXI` + `pickBench`. Home-nation players are unlimited.
- Growth: players_ar `plot` = weekly TI per player; 1 TI ≈ 0.1 skill pt (guide), 12 training weeks per season/age-year. `clubGrowth` = median recent TI per age band from YOUR squad (live 2026-11-04: teens 14-25, 20: 5-17, 23-25: 3-4, 26-27: 2-3, 28-29: 1-2, 30+: negative); `projectPlayer` applies it × talent (career pace vs your players that age) with the guide's hill-shaped allocation (`addTrained`). Guide: base TI dealt to 26, TI 1 at 27, decline from 28 → `PEAK_AGE` 27.
- Never leave a slot empty (can forfeit): GK↔outfield is `LAST_RESORT_RATING`, not impossible; bench fallback takes the best remaining player.
- Time: `match_data.match_time_of_day` is SERVER time (19:00) while pages display the user's zone (home showed 20:00) and that display zone CHANGED during one session — always measure, never assume (`measureTmOffset`; reserve kickoffs anchored to the first team's).
- Facilities: `facility_data` on /stadium/ (level, level_cost[], maintenance[], building); upgrade = `/ajax/stadium_change.ajax.php {facility, session_id: SESSION.id, level: current+1}` → `{success, level, cash}` | `{error}`.
- Transfer search: `/ajax/transfer.ajax.php {search: '/de/le/for/amin/19/amax/29/', club_id}` → `list[]` ≤100 rows WITH full skills, asi, `age` as years.months (18.11 = 18y11m), `fp_format`, `rec` (half-stars), `bid`; routine is null; also `next_bid` (minimum bid now — the asking price while `bid` is 0) and `time` (seconds left). No `/for/` = home nation only; youngest listed = 18.
- Page globals: `players_ar` (/players/), `test_lineup` (/matches/), facility JS on /stadium/

## Tactics page (`/tactics/`, `js/tactics_v2.js` — read + written live 2026-11-01)

- `players` / `on_field_assoc` are filled ASYNCHRONOUSLY (`tactics_init` posts `/ajax/tactics_get.ajax.php` → `{players, formation_assoc, formation, formation_subs, positions}`); at document-end they are still `{}`. Never read them — fetch that endpoint yourself (`loadTacticsPage`). The mentality/attacking/focus `<select>`s are server-rendered and safe to read.
- Squad fields (`players`: `skills[]` keyed `strength…set_pieces` / GK `handling…throwing`, star skills are `<img alt='20'>` strings, `skill_index` comma string, `routine`, `fp` "D/DM L" / "OM C, F", `injury`, `banned`, `status_no_check` holds the yellow-card ban-risk icon), `on_field_assoc` (key → player_id, "0" = empty), `cond_orders`, `reserves`, `national`, `miniGameId`.
- Slot keys + TM's position numbers: `gk`0 · `dl dcl dc dcr dr` 1-5 · `dml dmcl dmc dmcr dmr` 6-10 · `ml mcl mc mcr mr` 11-15 · `oml omcl omc omcr omr` 16-20 · `fcl fc fcr` 21-23. Bench `sub1`=GK `sub2`=DEF `sub3`=MID `sub4`=WING `sub5`=FWD (UI lists sub5 first). Roles `captain corner penalty freekick`.
- Out-of-position penalty is TM's own: `retPlayerMood(fp, posNumber)` → 0-4, each step = 10% (source comments: side C↔L/R 20%, L↔R 10%; one line 10%, D→F 40%; non-GK in goal 40%; capped 4).
- Save XI + bench + roles in ONE post: `$.post('/ajax/tactics_post.ajax.php', {on_field: <full 33-key map>, players: {pid: slotKey | 'out'}, reserves, national, miniGameId})` — roles are taken from `on_field`. Reply is HTML, not JSON (request `'text'`). Settings: same URL, `{save: 'mentality'|'attacking'|'focus', value, club_id, reserves, national, miniGameId}` → `[true, clubId, "0"]`.
- Conditional orders: `/ajax/tactics_co_post.ajax.php` with one `cond_orders[i]` record (keep its `ID`) + reserves/national/miniGameId → `{saved:true}`. EVENT 1=minute (PAR), 4=red card; COND 1=winning by PAR, 3=losing by PAR (negative), 4=any; ORDER 2=mentality (PAR1), 1=sub (PAR1 out, PAR2 in, PAR3 slot key). The page's own `co_save(0)` is a no-op (falsy guard) — post directly.
- Always read back after a reload (`tactics_get` `formation_assoc`, the three selects, `tactics_co_get`); `node --check` can't see any of this. Apply/Undo live in SECTION 5G and do exactly that (`saveTacticAndVerify` → reload → `verifyPendingApply`).
- Learning (SECTION 5I): `matchBank` = compact per-side features of every played division match (cap 600); `fitResultModel` = least squares GD ~ home + Δrec(stars) + Δlog-routine. Setting effects are residuals vs that model, per context, from OTHER teams only — we played one setting all season, so our own over-performance (`teamFactor`, shrunk k=10) would otherwise be credited to it (seen live). A setting overrides the heuristic only with n ≥ 12 per context and a gap > 1.5 SE.
- Time: TM prints every time (kickoffs, `#tm_clock`) in ITS zone — 1 h behind the user's browser (SAST) on 2026-11-01. `#tm_clock` is static server-rendered text (doesn't tick), so `measureTmOffset(doc)` on a fresh page = exact offset (rounded to 15 min); `parseKickoff` converts TM wall time → real instant and returns null when the offset is unknown. Tactics lock ~60 min before kickoff (user-reported; corroborated by the community script that reads the finished report 51 min out) — autopilot refuses inside lock + 10 min.
- Copilot = `runCopilot` (SECTION 5H), autopilot ON by default: match prep (opponent scan → reserves 5N → first-team tactics) once per fixture PAIR `A|B`; training once per `weekKey`; youth pull every pass; scouting daily; facilities weekly (off by default); one log entry with a line per step. Autopilot = the same run, unattended.
- Autopilot (SECTION 5H) works from ANY page — reads/writes are plain same-origin posts, settings are read from a fetched `/tactics/` (`<option selected>`). Guards: off by default, once per match id, ≥20 min between attempts, never inside the tactics lock + 10 min (`TACTICS_LOCK_MS`, `AUTOPILOT_SAFETY_MS`; refuses unparseable times), only when `opponentReadiness()` says the scanned opponent is the next fixture.
- Test changes on the live page without installing: push the work tree to a throwaway branch (`git commit-tree` + `git push origin <sha>:refs/heads/wip-x`, HEAD untouched), then in the signed-in browser pane `(0, eval)(await fetch('https://raw.githubusercontent.com/Jadax/tm-advisor/<sha>/TM_Advisor.js').then(r => r.text()))`. Delete the branch after.
